# Phase 3.5 — Vollständige Verzeichnislistung sofort sichtbar

## Problem

Beim Öffnen eines Google-Drive-Ordners in Nemo waren nur 10 Einträge sichtbar.
Weitere Einträge tauchten erst nach mehreren Sekunden auf — oder gar nicht.

## Ursache

Der ursprüngliche Code arbeitete mit einem Zwei-Phasen-Ansatz:

1. **`FetchDirFirstPage`** (pageSize=10) → erste 10 Einträge sofort abrufbar  
2. **`FetchDirPages`** (fire-and-forget) → restliche Einträge im Hintergrund

`readdir` wartete auf `FetchDirFirstPage`, rief dann `reply.ok()` mit 10 Einträgen
auf — und damit betrachtete der FUSE-Kernel die Listung als vollständig abgeschlossen.
`FetchDirPages` lief weiter, schrieb die vollständigen Daten in den Cache, aber
niemand rief `readdir` nochmals auf, sodass die übrigen Einträge nie angezeigt wurden.

Dasselbe Problem trat in `opendir`, `lookup` und `get_dir` auf: alle verwendeten
`FetchDirFirstPage` + `DirNavigate`, was zu inkonsistenten Teillistungen führte.

## Lösung

Die gesamte Zwei-Phasen-Maschinerie wurde entfernt:

| Entfernt | Ersetzt durch |
|---|---|
| `FetchDirFirstPage` / `DirNavigate` | `FetchDir` + `DirUrgent` |
| `FetchDirPages` (fire-and-forget) | — |
| `ApiOutcome::DirListingFirstPage` | — |
| `list_files_first_page` / `list_files_pages` | — |
| `store_dir_partial` / `append_dir_listing` | — |
| `TaskResult::DirListingPartial` | — |
| P-nav-Worker (6. Worker-Thread) | — (5 Worker verbleiben) |

Alle Codepfade (`opendir`, `readdir`, `lookup`, `get_dir`) verwenden jetzt einen
einzigen **`FetchDir`**-Aufruf mit pageSize=1 000.  Für die meisten Verzeichnisse
(< 1 000 Einträge) genügt **ein einziger API-Aufruf** (~300–500 ms).

### Progressives Laden

```
opendir  → FetchDir / DirUrgent  (startet Abruf sofort)
readdir  → wartet auf FetchDir   → serve_readdir mit ALLEN Einträgen
getattr  → sofortiger Cache-Hit  (store_dir_listing befüllt metadata-DashMap)
read     → lazy Download         (Nemo-Previews werden bei Bedarf geholt)
```

### Wichtige Einzelheiten

- **`opendir`** feuert `FetchDir` bereits ab, bevor `readdir` ankommt →
  bei warmem Cache ist `readdir` sofort fertig.
- **`serve_readdir`** ruft intern `obj.is_dir_complete()` auf — kein externer
  `bool`-Parameter mehr (war Ursache von Clippy `too_many_arguments`).
- **`read`** für große Dateien nutzt `if let Err` statt `match` mit
  `Ok(_) => {}` (Clippy `single_match`).
